## The Rule

**Invoke relevant/requested skills BEFORE any response or action** — before clarifying questions, exploring, checking files. Wrong fit? Drop it, no harm done.

**Before plan mode:** not brainstormed yet? Invoke brainstorming first.

Announce "Using [skill] to [purpose]", follow exactly. Checklist in skill → todo per item.

## Skill Priority

Multiple skills apply → process skills first (set approach), then implementation carries out. Brainstorming, systematic-debugging = common process skills, but rule holds for any. E.g.: "build X" → brainstorming then implementation; "fix bug" → systematic-debugging then domain skills.

## Red Flags

These thoughts mean STOP—you're rationalizing:

| Thought | Reality |
|---------|---------|
| "Just a simple question" | Questions are tasks. Check for skills. |
| "Need more context first" | Skill check comes BEFORE clarifying questions. |
| "Let me explore first" | Skills tell HOW to explore. Check first. |
| "I know what that means" | Knowing ≠ using. Invoke it. |
